# carousel 덱 다루기

덱은 1080×1350 슬라이드 여러 장을 담은 JSON 이다. **편집기 주인의 맥에서만
쓴다**(외부에 여는 AI 연결은 없다). 이 레포의 `apps/carousel` 에서 로컬 사본을
받아 고치고 올린다. 올리면 열어 둔 편집기에 바로 반영된다.

```sh
pnpm pull                    # 내 덱 전부 → decks/<폴더>/deck.json + assets/
pnpm export <폴더>           # 로컬 사본을 찍어 decks/<폴더>/export/ 에 JPEG·layout.json, 배치 경고 출력
pnpm push <폴더> [--force]   # 고친 사본 올리기(새 이미지도 같이). deck.json 에 id 가 없으면 새 덱
```

`.env.local` 의 `SUPABASE_PROJECT_REF`·`CAROUSEL_OWNER_ID` 와 Supabase CLI
로그인이 필요하다.

## 작업 순서

1. `pnpm pull` 로 받는다. 새로 만들 땐 `decks/<새 폴더>/deck.json` 을 아래
   형식으로 쓴다.
2. JSON 을 고친다. `id`·`updated_at` 은 건드리지 않는다.
3. 새 이미지는 `decks/<폴더>/assets/` 에 복사하고 `src` 에 `assets/<파일>` 과
   원본 크기 `nw`·`nh` 를 적는다. 한글 파일 이름은 push 가 ASCII 로 바꿔 올린다.
4. `pnpm export <폴더>` 로 결과를 직접 본다(JPEG 을 이미지로 읽는다). 배치는
   규칙이 정하므로 겹침·여백 걱정은 없다. "아래 여백을 넘쳐요" 경고가 나오면
   글을 줄이거나 장을 나눈다.
5. `pnpm push <폴더>`. "앱에서 바뀌었어요"로 거절되면 사용자가 그사이 편집기에서
   고친 것이다. 다시 pull 해서 그 위에 고친다(`--force` 로 덮어쓰지 않는다).
6. 사용자에게 무엇을 바꿨는지 알리고, 마지막 판단은 편집기에서 해 달라고 한다.

## 형식

```jsonc
{
  "id": "…",
  "updated_at": "…", // pull 이 채운다
  "title": "버스앱 리뷰 2편", // 내보낸 파일 이름이 된다
  "caption": "게시물 본문\n\n#해시태그", // 인스타 게시물 글
  "watermark": "@아이디", // 읽기 전용(계정 설정). push 는 무시한다
  "slides": [
    // 장 순서대로
    {
      "valign": "top", // top | center · 쌓은 묶음을 위에서 시작할지 세로 가운데에 둘지
      "layers": [
        // 배열 순서대로 위에서 아래로 쌓인다
        {
          "type": "text",
          "style": "body", // body(40px) | caption(30px 회색, 출처용)
          "color": "black", // black | red · 상자 전체 색
          "text": "첫 줄\n**굵게** ==빨강== __밑줄__ ||블러||",
        },
        {
          "type": "image",
          "src": "assets/…",
          "nw": 1736,
          "nh": 3528,
          "full": false, // true 면 좌우 끝까지(폭 1080), 아니면 본문 폭(920)
          "crop": { "x": 0, "y": 0, "w": 1, "h": 0.4 }, // 원본에서 보일 영역(0~1). 이 예는 위 40%
        },
      ],
    },
  ],
}
```

- **좌표가 없다.** 요소는 배열 순서대로 위에서 아래로 쌓이고, 가로는 왼쪽
  여백(80px)에 붙는다(꽉 채운 그림만 0). 요소 사이는 본문 한 줄(57.6px), 위·아래
  여백은 120px. 나란히 놓기·겹치기는 없다(정 필요하면 코드 레이어로 그린다).
- **이미지 속 글자는 캔버스 기준 20px 이상**(목표 24px, 캡션 30px 보다 조금 작은
  정도. 1편의 견본이 이 크기다). 웹 캡처는 2배율로 찍으면 본문 14px 가 28px
  이니, 폭 1300px 이하로 잘라 920px 자리에 넣어야 기준을 넘는다. 제목이 잘려도
  글자가 작은 것보다 낫다. 전후 비교 패널은 `skills/carousel/compose.mjs` 로
  만든다.
- 각 장 하단 가운데 약 1290~1340px 에 워터마크와 장 번호가 자동으로 들어간다. 그
  자리는 비워 둔다.
- 텍스트
  - 글꼴은 Pretendard 하나, 굵기는 보통·굵게만, 크기는 본문 40·캡션 30 고정이다.
    크기를 바꿀 방법은 없다.
  - 상자 너비는 내용에 맞춰진다. 줄은 `\n` 으로 직접 나눈다(한 줄에 한국어 20자
    안팎이 읽기 좋다). 오른쪽 여백(폭 920)에 닿을 때만 단어 단위로 접힌다.
  - 줄 간격은 57.6px(본문). 여러 줄 상자의 높이는 대략 줄 수 × 57.6. 글이 많아
    한 장(위아래 여백 빼고 1110px)을 넘치면 export 가 경고한다.
  - 강조는 `**굵게**`, `==빨강==`, `__밑줄__`. 빨강은 핵심 한두 곳에만 쓴다.
    `||블러||` 는 글자를 흐리게 가린다(스포일러·민감한 말).
- 이미지
  - 새 이미지는 `assets/` 에 넣고 push 가 올린다. `nw`·`nh` 는
    `sips -g pixelWidth -g pixelHeight <파일>` 로 잰다.
  - 크기는 배치가 정한다. 폭은 920(본문 폭) 또는 1080(`full`), 높이는 크롭한
    비율대로. 장에 남은 높이보다 크면 비율을 지킨 채 줄어든다(세로로 긴 캡처는
    폭이 좁아진다).
  - 일부만 보여 주려면 `crop` 을 고친다(원본 대비 0~1). 폭이 고정이라 좁게
    자를수록 확대된다. 편집기에선 그림을 더블클릭해 손잡이·끌기로 한다.
  - 투명 PNG 는 장 바탕(흰색) 위에 그려진다.
- 확인(`pnpm export`)
  - 편집기와 같은 렌더러를 헤드리스 크롬으로 찍는다(원본 크기 1080×1350). 앱의
    "JPEG 내보내기"와 픽셀 단위로 같다.
  - `layout.json` 은 장마다 레이어 상자(`index`, `boxes`: 캔버스 px 의
    `id`·`type`·`x`·`y`·`w`·`h`)다. 실제로 얼마나 차지했는지 볼 때 읽는다.
  - 기기 화면 캡처에 프레임을 씌우려면 `device-frame` 스킬이나
    https://carousel.yeolyi.com/frame 을 쓴다.
- 레이어에 `id` 가 있으면 그대로 둔다. 새 레이어엔 안 적어도 된다.
