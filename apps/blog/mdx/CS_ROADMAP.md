# CS 시리즈 로드맵

## 파트 1: 0과 1로 컴퓨터 조립하기

1. 컴퓨터의 손가락이 두 개인 이유 (`zero-and-one`)
2. 전기가 논리를 배우다 (`boolean`)
3. 컴퓨터는 엄마가 좋은지 아빠가 좋은지로 구성됨 (`and-or-not`)
4. 사실 엄마 아빠가 둘 다 좋지는 않았던 컴퓨터 (`nand-is-all-you-need`)
5. 컴퓨터도 골라야 할 때가 있다 (`mux`)
6. 스위치로 만든 계산기 (`adder`)
7. 앞자리가 뒷자리한테 넘기는 것 (`full-adder`)
8. 기억상실증 걸린 컴퓨터 고쳐주기 (`sequential`)
9. 컴퓨터에게 박자감 가르치기 (`flip-flop`)
10. 계산만하면 계산기지 그게 컴퓨터니? (`turing-machine`)
11. 컴퓨터 조립법은 폰 노이만에게 (`von-neumann`)
12. CPU와 대화하기 (`instruction-set`)
13. 가져오고 해석하고 실행하고 (`cpu`)
14. 계산은 빠른데 떠올리는 건 느린 컴퓨터 (`cache`)

> 파트 1→2 전환: 14번 마무리에서 **컴퓨터의 구조를 알았으니, 이제 데이터를
> 효율적으로 다루는 방법이 필요하다** 동기 연결.

## 파트 2: 컴퓨터스럽게 문제 해결하기

1. 할 일을 쪼개면 그게 알고리즘 (`data-structure-and-algorithm`)
2. (제목 미정) — 메모리 위에서 데이터를 조직하는 두 가지 기본 방식: 연속
   할당(contiguous)과 포인터 연결(linked) (미작성)
   <!-- 참고: Skiena, *The Algorithm Design Manual* 3.1 "Contiguous vs. Linked Data Structures".
        연속 할당 = 하나의 메모리 블록에 나란히 배치 (배열, 행렬, 힙, 해시 테이블).
        포인터 연결 = 별개의 메모리 조각을 포인터로 이음 (리스트, 트리, 그래프 인접 리스트).
        파트 1에서 다룬 메모리/주소 개념과 자연스럽게 이어진다. -->
3. 나란히 놓거나, 연결하거나 (`array-and-linked-list`) (미작성)
   <!-- 연속 할당과 포인터 연결의 첫 번째 응용: 배열과 연결 리스트 -->
4. 신분 상승이 쉽지않은 알고리즘 세계 — 시간 복잡도 (미작성)
   <!-- 한계: 효율을 재는 도구가 생겼으니, 배열과 리스트 위에 접근 패턴을 제한해보자 -->
5. 늦게 온 사람이 먼저 들어가는 식당 — 스택과 큐 (미작성)
   <!-- 한계: 데이터를 저장했으면 이제 정렬해야 한다 -->
6. 느려터진 정렬 삼형제 — 버블, 선택, 삽입 정렬 (미작성)
   <!-- 한계: 단순 정렬은 데이터가 커지면 너무 느리다 -->
7. 나누고 합치면 빨라진다 — 머지 정렬, 퀵 정렬 (미작성)
   <!-- 한계: 분할 정복 말고 다른 방법은 없을까? 트리 구조를 알아야 한다 -->
8. 컴공생들은 나무가 어떻게 생겼는지도 몰라 — 트리 (미작성)
   <!-- 한계: 트리를 활용하면 정렬도 할 수 있지 않을까? -->
9. 트리로 정렬까지 — 힙과 힙 정렬 (미작성)
   <!-- 한계: 정렬된 데이터를 탐색하는 건 좋지만, 그래프 전체를 탐색하려면? -->
10. 하나만 파는 애 vs 정신이 좀 산만한 애 — DFS, BFS (미작성)
    <!-- 한계: 탐색은 해결했지만, 데이터를 단번에 찾는 방법은 없을까? -->
11. 될 때까지 해보는데 성과도 좋은 자료구조 — 해시 테이블 (미작성)

> 파트 2→3 전환: 9번 마무리에서 "프로그램이 여럿 돌아가면 누가 자원을 관리하나"
> 동기 연결.

## 파트 3: 프로그램이 혼자 쓰는 컴퓨터는 없다

1. CPU 쉬는걸 못참는 악랄한 개발자들이 만든 것 — 운영체제의 등장 배경 (미작성)
   <!-- 한계: OS가 하드웨어를 관리하는데, 프로그램은 어떻게 OS에게 요청하나? -->
2. 내가 내 컴퓨터의 모든 기능을 쓸 수 없는 이유 — 시스템 콜 (미작성)
   <!-- 한계: 요청은 할 수 있게 됐는데, 프로그램이 여러 개면? -->
3. 일잘러 컴퓨터의 할 일 관리법 — 프로세스와 스레드 (미작성)
   <!-- 한계: 프로세스마다 메모리를 통째로 주면 금방 바닥난다 -->
4. 게임 설치 용량이 50기가인데 램도 50기가 사야하나요? — 가상 메모리 (미작성)

> 파트 3→4 전환: 4번 마무리에서 "한 컴퓨터 안에서 자원을 나눠 쓰는 법은
> 알았는데, 컴퓨터끼리는 어떻게 대화할까?" 동기 연결.

## 파트 4: 컴퓨터끼리 대화하는 법

1. 옆자리 친구에게 쪽지 보내기 — 네트워크의 탄생과 패킷 (미작성)
   <!-- 한계: 쪽지는 보낼 수 있는데, 제대로 도착했는지 어떻게 알지? -->
2. 택배가 분실되지 않는 이유 — TCP와 신뢰성 (미작성)
   <!-- 한계: 같은 네트워크 안에서는 되는데, 전 세계로 보내려면? -->
3. 주소만 알면 어디든 찾아간다 — IP와 라우팅 (미작성)
   <!-- 한계: 데이터는 도착하는데, 브라우저가 서버와 대화하려면? -->
4. 브라우저 주소창에 URL을 치면 일어나는 일 — DNS와 HTTP (미작성)
